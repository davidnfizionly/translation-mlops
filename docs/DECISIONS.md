# Architecture Decision Records

One line each: what, why, what was rejected.

- **ADR-001 Dataset under CC BY-NC 4.0 accepted.** The English-Nuer-Dinka parallel corpus by Tajnaam is the only large human-oriented corpus found for both languages; this is a non-commercial portfolio project. Rejected: the MIT-licensed health dataset from the same publisher, because all its Nuer and Dinka text is Google Translate output (stated on its card).
- **ADR-002 No dataset, weights or fine-tuned model published.** Both the dataset and NLLB-200 are CC BY-NC 4.0; the repository holds a download script and a few attributed sample pairs, the fine-tuned weights stay in a private S3 bucket and are deleted at cleanup. Rejected: publishing the fine-tuned model on Hugging Face.
- **ADR-003 Widget runs locally behind a local proxy, no public API.** Keeps the endpoint private and avoids offering a translation service built on non-commercial data and weights. Rejected: API Gateway or a public website.
- **ADR-004 Backend stack keeps local state.** The state bucket cannot hold its own state before it exists; `infra/backend` uses a local, git-ignored state file, and every other stack uses the S3 backend with `use_lockfile`. Rejected: a DynamoDB lock table (no longer needed with S3 native locking).
- **ADR-005 State bucket name gets a random suffix and is passed through a git-ignored `backend.hcl`.** Avoids an account ID in a bucket name and in public files. Rejected: account ID in the bucket name.
- **ADR-006 The budget lives in the backend stack and is created first.** The bucket `depends_on` the budget so the budget exists before any other resource; no notifications, as requested; it covers the whole account (credits and refunds excluded), because a tag filter would need the Project cost allocation tag activated first. Rejected: a separate budget stack (one more state to manage for one resource).
- **ADR-007 Region us-east-1.** EC2 access is already validated in this account and the SageMaker GPU quotas needed exist there. Rejected: other regions.
- **ADR-008 Keep the corpus despite very probably machine-generated targets, and clean it before the split.** It is still the only large parallel source for both languages; looping and broken rows are removed before the test set is drawn so the test set does not reward broken references. Metrics are reported as agreement with machine-generated references. Rejected: dropping the project dataset, or cleaning only the training split.
- **ADR-009 Cleaning and split in pure-standard-library Python, the same module locally and in the Glue job.** One implementation, testable offline, identical output in the cloud. Rejected: a separate Spark rewrite for Glue (two implementations to keep in sync for 500,000 rows that fit in memory).
- **ADR-010 Group-aware split with fixed sizes (2,000 test, 2,000 validation) from a hash order.** Rows whose English differs only in numbers share a group and land in the same split; a hash order makes the split deterministic without a random state. Rejected: a random row-level split (near duplicates across splits).
- **ADR-011 Base model nllb-200-distilled-600M, pinned to revision f8d333a0.** Smallest NLLB-200 variant; it covers dik_Latn and nus_Latn, fits a 16 GB T4 (ml.g4dn.xlarge, 0.736 USD/hour) for fine-tuning with fp16 and Adafactor, and keeps every launch well under the 20 USD cap. Rejected: the 1.3B and 3.3B variants (larger GPUs, several times the cost per hour).
- **ADR-012 Hugging Face training image 2.8.0 with transformers 4.56.2 (CUDA 12.9), inference image 2.6.0 with transformers 4.51.3.** Listed in the AWS Deep Learning Containers ECR registry; CUDA 12.9 supports the T4 GPU of g4dn instances. Rejected: the 2.9 and 2.11 images (CUDA 13 and transformers 5, two major changes at once).
- **ADR-013 Promotion rule fixed before any fine-tuned result: fine-tuned chrF must be higher than the baseline chrF in every direction.** chrF is the primary metric for these morphologically rich, low-resource languages; BLEU is reported next to it. The gate refuses to compare reports with a different test file, row count or decoding settings. Rejected: an average over directions (one direction could get worse unnoticed).
- **ADR-014 Training and evaluation jobs started with boto3 (create_training_job, create_processing_job), not the SageMaker SDK.** The request is explicit and reviewable; the SDK 2.x line is on a deprecation path and the 3.x line did not install cleanly. The SDK stays pinned (2.257.7) in a tooling image only where Pipelines need it. Rejected: an unpinned SDK.
- **ADR-015 Two IAM wildcards kept: `ecr:GetAuthorizationToken` and `cloudwatch:PutMetricData` on `*`.** Neither action supports resource-level permissions; PutMetricData is limited by a condition to the `/aws/sagemaker/*` namespaces, and image pulls are limited to the two Hugging Face repositories. Rejected: AmazonSageMakerFullAccess (far broader).
- **ADR-016 Decoding fixed at beam 4 and 200 new tokens for every evaluation.** Chosen before the first evaluation and not changed after seeing outputs; the base model's looping Dinka outputs are reported as they are. Rejected: adjusting decoding (for example a repetition penalty) after looking at test outputs, which would be tuning on the test set.
- **ADR-017 Pipeline definition written in Terraform as JSON (`aws_sagemaker_pipeline`), not generated by the SDK at run time.** The definition, its role and its code objects are versioned and planned like the rest of the infrastructure; no account-specific definition file is committed. The JSON keys follow a reference definition generated offline with the pinned SDK 2.257.7, and `pipelines/tests/` checks the planned definition. Rejected: `pipeline.upsert()` from a notebook or script (state outside Terraform).
- **ADR-018 The gate is the approval: a version is registered as `Approved` only on the If branch of the chrF condition; the Else branch is a Fail step.** A failed gate is visible as a failed execution with its reason, and nothing is registered. Rejected: registering every run as `PendingManualApproval` (a manual click would replace the measured rule).
- **ADR-019 Full run sized from the measured smoke speed: 50,000 training rows (100,000 examples over two directions), 3,000 steps of 32 examples, about 0.96 pass over the subset, hard limit 2 hours.** 0.562 steps per second on one T4 gives about 89 minutes of training, about 1.19 USD on demand. Rejected: the full 453,106-row split, and managed spot training until checkpoint resume is verified. Recomputed after run 2 from its billed time (96,000 examples in 4,024 s): one pass over the full split (906,212 examples) would take about 10.6 hours and 7.77 USD. That is under the 20 USD cap, but it puts about 39% of the cap on one job with no tested checkpoint resume, after a run that had already failed at step 1,700; the 2-hour job limit was kept.
- **ADR-020 Version 1 of the model package group registered with `scripts/register_model_version.py` (CreateModelPackage) instead of a pipeline Register step.** The Register step of execution lftys35r436m failed twice (missing IAM action, then metadata values rejected by the API) after Train, Evaluate and the chrF gate had succeeded. The script copies the Register arguments from the live pipeline definition, resolves them to that execution's real model artifact and evaluation.json, and refuses to run unless Train, Evaluate and ChrfGate succeeded with a True outcome. Tradeoff: the version is not linked automatically to the execution in SageMaker lineage; the link is the metadata (pipeline_execution_id, training_job, evaluation_job, registered_by) and the S3 paths. Versions take no tags, so the Project tag is on the group only. Rejected: a new full execution (about 1 USD of GPU time to reproduce a model that already passed the gate) and a retry of the failed execution (it most likely reuses that execution's original definition, not verified).
- **ADR-021 Endpoint built from the approved registry version (model package ARN) on one ml.g4dn.xlarge, no auto-scaling, in its own stack.** The image and artifact served are the ones the chrF gate evaluated. One instance is enough for a single-user demo; auto-scaling would only add instances that bill. Rejected: CPU hosting on ml.m5.xlarge (beam search over 600M parameters on CPU makes each request take seconds; not measured on SageMaker), serverless inference (no GPU support).
- **ADR-022 Data capture enabled at 100% to the ml bucket (`datacapture/`), SSE-S3.** Server-side record of every request and response for the drift report, at storage cost only. Rejected: SageMaker Model Monitor schedules (processing jobs that bill per run, not needed for a one-hour session).
- **ADR-023 Drift and cost metrics published by the local proxy (`TranslationMlops` namespace: InputWords, OutputInputRatio, EstimatedRequestCostUSD).** The serving container stays unchanged and the proxy already measures each request. The proxy uses the CLI credentials; `cloudwatch:PutMetricData` needs no new role. Rejected: metrics emitted from inside the container (needs a new image or role permission for a custom namespace).
- **ADR-024 No customer KMS key on the endpoint configuration.** ml.g4dn.xlarge uses NVMe instance storage, which AWS encrypts in hardware, and the endpoint configuration does not accept a KMS key for instance types with local storage. Traffic to the runtime API is HTTPS. Rejected: a customer managed key (monthly cost, not applicable to this instance storage).
- **ADR-025 Alarms without actions.** The two alarms (5XX errors, p90 latency) show their state on the dashboard; no SNS topic or e-mail, as for the budget. Rejected: e-mail notifications (no inbox is watched during the demo, and the project avoids e-mail endpoints).
